# Network gate failure cases

Test plan, not test results. Run in a temporary host home with a fake provider, clock, probe and command runner. Unknown commands must fail in the fake, never fall through to macOS.

- Start or restart with the gate enabled but no sample, an expired sample, a failed plugin load, a bad certificate, HTTP error, redirect to login, failed AppleScript or the wrong configuration. Admit no model traffic. In particular test both mismatches: probe works but VPN is down; VPN is connected but probe fails. A late successful check from before a settings change must not open the gate.
- Queue a chat input and a worker while closed; include the Host agent, queued follow-ups, recovered work, a nested reviewer and summaries. Assert no turn starts and the fake provider receives zero requests. Open the gate: each pending input is placed once, in order within its conversation. With no configured gate, normal admission still works.
- Drop the stream after a tool with a recorded result. Exercise a thrown fetch error and a terminal SSE error before the next poll. Across several polls, flaps and a restart on either side of resume submission, expect a paused turn, then one continuation of that conversation, one tool effect and one final report. No replacement Job or duplicate owner input. A healthy-network auth/quota failure, user Stop or project pause must not become an automatic retry.
- Hold the gate beyond the idle and stall thresholds; include a provider that ignores abort and sends a late tool call. No timeout, stall notice or execution from the stale stream. Reopen: normal watchdogs work again with fresh deadlines. Stop while waiting: no leaked waiter or later continuation.
- With a fake Wi-Fi port other than en0, cross 60 s of continuous RECONNECTING or DISCONNECTING; verify command order, including power restoration on error. A brief transient, changed state, unknown device, Wi-Fi originally off, no connectivity or overlapping tick must not cycle Wi-Fi. Disconnected with a working uplink attempts connect, not a power cycle.
- Fail every repair. Assert bounded attempts, increasing backoff, one owner notice per outage across restart, continued read-only polling and recovery without owner input. No repair counts as readiness without a fresh check. Restart after simulated power-off: restore only the recorded device we turned off.
- Drive Settings → Plugins on the private host: compare waiting, repairing, last repair/failure count and ready with fake command history; capture a screenshot. No live probe, Wi-Fi change or Tunnelblick access in verification.
