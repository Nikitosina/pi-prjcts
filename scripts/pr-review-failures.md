# Review room failure contracts

Use a fresh temporary project home, a local origin and a stub `gh`. A dirty checkout stays on its branch and keeps staged, unstaged and untracked files when review fetches a private PR ref. A moving remote must not substitute another head for a requested SHA. Files and context must come from commit blobs, never from the worktree. An ordinary push has a head-to-head diff; a changed merge base has a file list and no interdiff. Viewed marks survive unrelated changes, not changes to the marked blob. Invalid PR numbers, traversal, git pathspecs and unbounded line ranges must fail before opening a project runtime. An unavailable provider, excessive output or missing commit must not appear as an empty successful review.

Browser journey: independently listed PRs and chat references open the center. Switching iterations or files cannot display a stale result. Unified and split rows preserve line anchors; provider HTML is text. Expand context at the selected SHA. Check narrow overflow, generated-file collapse and Esc back to chat.

Compare Files mode to combo at desktop and narrow widths. Split must align replacement pairs and hatch the missing side, unified must retain both gutters, and expanding a hidden gap must add numbered context from the selected revision. Verify scroll spy, local Viewed, collapsed resolved discussions, context jumps, iteration selection and both room entry points.

Phase 2: Saving, editing or deleting a draft must not deliver a chat message. Reopening the room preserves pending and sent comments, including the quote and anchor at the original head when a line disappears. A colleague PR offers local provider drafts but no worker actions. A worker batch must match the confirmed preview, go once to the Job's own Coordinator, and mark only those drafts sent. Concurrent edits must not change what the owner confirmed. Switch layouts with the probe in the gap after a long file: the next file boundary must stay still. A failed thread jump must show an error instead of selecting an invisible thread. Switching layouts while typing keeps the quote selection and text. A long thread can be shortened before saving. Selecting an older iteration must not make an outdated anchor current again. Reopen after sending from another chat and check the stored timestamp and the Job chat's transcript.

Phase 3: Confirm one provider review for the displayed PR, head, verdict, summary and selected text only. Unselected worker drafts stay pending. A stale head or concurrent edit invalidates confirmation; thread mutations must belong to this PR. Record intent before the provider call: timeout, lost answer, restart or duplicate submit must not repeat it. The owner sees uncertainty and a PR link. Published drafts leave pending; refresh shows the new thread, replies and resolution. Agent and Coordinator tools cannot publish.

Phase 4: One click requests one scout through the Coordinator of the Job chat (or the opening chat for a colleague PR), never as an owner message. Pin the brief and result to the fetched head. Reject incomplete or duplicate coverage, off-diff notes and oversized answers with actionable reasons. A stopped scout must not leave the room busy. A push marks only affected steps, never starts a scout, and a manual rebuild preserves the current step if possible. Approving marks only that step’s files viewed.
