# Arc projects, slice S1 (detect + grant + seams + fakes): failure cases (written before code)

Scope: `src/vcs.ts` (CLI seams `PI_PROJECTS_ARC_CLI` / `PI_PROJECTS_ARC_WT_CLI` / `PI_PROJECTS_ARCANUM_CLI`, Arc detection, subpath), seams in `src/workspace-isolation.ts`, Arc whole-repository grant through the existing one-click flow, `arcAuthorization` ("Connect Arcadia"), Settings UI. Fakes only: `scripts/fake-arc.mjs`, `scripts/fake-arc-wt.mjs`, fixture `scripts/lib/fake-arc-kit.mjs`. E2Es: `scripts/arc-detect-grant-e2e.mjs` (UI, grant, skills sources) and `scripts/arc-isolation-e2e.mjs` (allocation, reconcile, release against the fakes; replaces the four real-Arcadia scripts).

1. A test or the host touches the real `~/arcadia`, `~/arcadia-wt`, `~/.arc`, a real arc mount, Arcanum or CI because a binary path is hard-coded. Guard: seams; E2E asserts every fake call's cwd is under the temp root, no logged string contains the real path, and `arc-wt --force` never appears.
2. Detection false positives/negatives: a git project treated as Arc (or the reverse), a non-repo directory, a git repo nested below an Arc marker, a missing `.arc`, a symlinked cwd. Git projects must see no behaviour change and spawn no arc process.
3. Subdirectory project (`mobile/nlp/ios/keyboard`): ownerCheckout must be the Arc root, the subpath must be stored and frozen with the grant (fingerprint), cwd at the root gives an empty subpath.
4. `arc root` disagrees with the walked root, `arc info --json` fails / lacks `repository`, or `arc-wt config` lacks `object_store_path` / `worktrees_base_path`: a blocker with a message, no grant written.
5. Worktree root inside the Arc root, or equal to it: refused. Missing worktree root is created (mode 0700) only after validation.
6. Base revision: the owner mount is on a feature branch; the grant must record the trunk head (not the current HEAD). `arc log` failing or returning a non-hash: blocker.
7. Dirty owner mount: preview warns but the grant stays possible; the dialog says workers start from trunk, not the owner's branch.
8. A GitHub whole-repository grant already exists: the Arc grant is refused (provider immutable). An Arc grant already exists: second quick grant is refused ("already edit this repository"). Stale expectedRevision refused.
9. Connect Arcadia: requires the Arc whole-repository grant; records repository, login (from `arc info`), base `trunk`, workspace revision, owner; idempotent (second confirm refused as connected); follows workspace grant changes (rebind) like one-click GitHub; revoke clears or stales it; never calls arcanum or the network.
10. GitHub projects regress: step 2 still "Connect GitHub", fingerprints of existing GitHub repositories unchanged (subpath omitted when absent), project files without `arcAuthorization`/`subpath` load.
11. Settings UI: Arc project shows "Arcadia (arc)" steps and dialog texts (arc-wt worktrees, subpath, trunk base) not git texts; no GitHub button for Arc; fits 390 px; no console errors.
12. Skills: arc, arc-wt, arcanum-go, arcadia-ci under `~/.agents/skills` must be candidates in the skills picker and `/` menu; `~/.claude/skills` sources are reported (not assumed). A skill with `disable-model-invocation` (arc-wt) is listed but stays out of the prompt index.
13. Isolation against the fakes (arc-isolation E2E): allocation carries exact lease owner/store facts; foreign lease owner refuses; shared-store mismatch or repository mismatch is blocked/uncertain; active consumer cwd blocks release; dirty worktree preserved; clean release uses `lease renew` then `remove --lease-owner --lease-renewed` (never `--force`); crash after `arc-wt add` is reconciled to the same receipt without re-adding; path escape and existing target refused.
14. The four scripts that used the real Arcadia (`durable-workspace-arc-e2e`, `durable-workspace-arc-existing-thread-e2e`, `durable-workspace-original-intent-reconcile`, the Arc half of `workspace-allocation-e2e`) are removed or cut to their git half.
